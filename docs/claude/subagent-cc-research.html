Claude Code Subagent 能力调研

调研日期: 2026-05-19 · 背景: OpenPipal subagent 接入完整收尾（P1–P6, 5 commits）后的 cc 能力对照 · 结论: 3 项有价值差距值得后续做（maxTurns / parallel / memory），其余 cc 能力多数对 OpenPipal 不适用
这份文档的价值：不是"cc 能力清单"或"差距列表"——是"按 OpenPipal 产品形态筛过的、未来真触发某些场景时知道改什么"的决策路径。 cc 是 coding agent，OpenPipal 是 docked 桌面伴侣，产品形态不同导致很多 cc 能力（如 worktree 隔离、Fork 模式、CLAUDE.md 自动注入）对我们就是不适用。

2.2 调用与隔离

  • Agent Tool 参数: subagent_type (string, 必填) + prompt (string, 必填)
  • 自动委托: Claude 根据任务描述与 description field 语义匹配（OpenPipal 主 agent 也是这种模式）
  • @-mention: @agent-code-reviewer 强制选定（OpenPipal 没有，用户在 prompt 里说 "用 subagent profile='xxx'" 就行）
  • 上下文隔离: 独立上下文窗口，tool calls 不污染主对话——跟 OpenPipal 设计一致
  • 返回数据: 仅 final message 文本——跟 OpenPipal 一致（finalText 不展示给用户）

2.3 并行 / 链式 / 嵌套

能力ccOpenPipal
并行（一次发起多个）✓ 多个 Agent tool calls✗ 首版只 single（deferred）
链式（A 输出当 B 输入）✓ 主 agent 手动串主 agent 多次单独调用即等价
嵌套（child 再开 child）✗ 官方明确禁止✗ 黑名单 'subagent' 防套娃，跟 cc 一致

2.4 Memory 跨 session 学习（最有意思的能力）

memory: user     # ~/.claude/agent-memory/<agent-name>/
memory: project  # .claude/agent-memory/<agent-name>/
memory: local    # .claude/agent-memory-local/<agent-name>/
  • Subagent system prompt 自动注入: Read/Write/Edit 权限 + MEMORY.md 首 200 行
  • Subagent 可主动 update MEMORY.md（记录 codebase patterns / 经验）
  • 下次启动自动加载，形成累积知识库
  • OpenPipal 已有 ~/.openpipal/memory/<role>/ 主 agent 记忆，但 subagent 没单独空间

2.5 流式 / 进度 / 中断

  • cc /agents 命令打开管理面板，Running 标签显示活跃 subagent
  • 后台 subagent 在下方面板展示状态条 + 进度
  • 前台 Ctrl+C 中断同主会话
  • 后台 /agents 选中 + x 中断
  • OpenPipal 现状: 流式中间状态没做（P5 deferred），调用时卡 5–15 秒

3. 价值差距矩阵（按优先级）

差距价值成本加入理由
maxTurns 字段 High 30 min 防 runaway——child 卡 50 轮还没完会烧 token + cost 双重失控。安全网
memory: field 跨 session 学习 High 半天 让 researcher / executor 等档位跨调用积累领域经验，long-term 价值大；OpenPipal memory 体系已有，扩展到 subagent 级别是对称设计
parallel 调用（多 subagent 并发） High 半天 用户委派"同时调研 A/B/C"时省 3 倍时间。pi-tools subagent 工具 schema 扩展 + runner 并发管理
disallowedTools 黑名单字段 Medium 1 小时 比白名单灵活——"几乎全工具但禁 web_search"这种 case 更易表达
color 区分 UI Medium 1 小时 主对话出现多个 SubagentCard 时一眼分辨
effort 字段（thinkingLevel per profile） Medium 2 小时 thinker 高 thinking、explorer minimal——按 profile 优化成本/质量；但 OpenPipal 模型层可能挂 model 字段更对齐
/agents 管理界面（GUI 化） Medium 一天+ OpenPipal 是 GUI 应该走 Settings 而不是命令；UI 工作量大；当前 vim md 文件够用
流式中间状态 Medium 一天 实时看到 child 在调什么工具；adapter 加 tool_execution_update case + chatStore 流式累积 + SubagentCard 进度条
Worktree 隔离 / Fork 模式 Skip — cc 是 coding agent 才需要——OpenPipal 不 commit 代码 / Fork 跟"上下文隔离"哲学冲突
CLAUDE.md 自动注入 Skip — OpenPipal 不是 IDE，没"项目级 CLAUDE.md"概念
SendMessage / Agent Teams Skip — cc 自己标 experimental；OpenPipal 现阶段过早

4. 用户拍板的 3 项 (2026-05-19)

选定加入候选（按"具体触发再做"原则，不立即动手）：
  1. maxTurns — 防 runaway 安全网（30 min 工作量，性价比最高）
  2. parallel — 多 subagent 并发（半天工作量，等用户真实使用反馈有"同时派几个"的需求再做）
  3. memory — 跨 session 学习（半天工作量，产品理念决策——让 subagent 从"throw-away 工具"变成"会成长的专家"）
其它差距不考虑。
