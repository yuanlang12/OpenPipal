# 规则（hook）

用户说"以后读成绩表先把名字遮掉"，这不是一次性的活，是一条要一直生效的规则。
规则靠代码保证，不靠记性：写成一个小文件，App 每轮都会执行它。

什么时候该定规则、什么时候不该，`set_rule` 工具的说明已经写清；本技能只讲**怎么把要求递交得清楚**，
以及递交之后用户会看到什么。拿不准是不是规则，问一句："这条以后每次都要这样吗？"

## `set_rule` 怎么填

- **description**：一句大白话，照用户原话写，用户会在提示里看到这句。例：`读成绩表前先遮名字`
- **details**：给后台写规则的人看，把触发条件和要做的事说具体。规则能做的只有三种事，照这个说：

| 事件 | 什么时候 | 能做什么 |
|---|---|---|
| `tool_call` | 工具执行前 | 改参数；或拦下 |
| `tool_result` | 工具执行后、模型看到之前 | 改结果 |
| `before_agent_start` | 每轮开工前 | 往系统提示里加一段 |

例：`details = "read 工具读到路径含 成绩/grade/score 的文件时（tool_result），把正文里的姓名换成 学生1、学生2"`

- 规则里要跑命令 / 读文件（"每次改完代码就跑 pytest"）：照样递交，把要跑的命令写进 details，后台会用它借助手的工具。
- 作用范围：在独立 Agent（我的 Agents）里定的规则写进它自己的目录，**只对这个 Agent 生效**并跟着它走；要对所有 Agent 生效，请用户到通用助手里说。只对某个内置角色生效的写明（"只在编码助手里"），后台会按角色名判。
- 用户要改一条已有的规则：再调一次 `set_rule`，description 照旧，后台会改同一个文件。

## 递交之后

- 后台写好后，App 会在对话下方居中显示一枚胶囊「已定下规则：…」，写坏了会显示原因并自动改一次。
  你不用等，也不用替它宣布结果——回复用户时一句带过："这条规则已交给后台，写好会提醒你。"
- 用户问规则定没定、或再提同一条：以系统提示里 `<rules>` 清单为准——生效中 / 没生效（带原因）/ 后台正在写。不在清单里就是没定下，别说"已经完成"；用户再提就再递交一次。
- 用户要撤销：胶囊上有「撤销」，插件页（local-rules）也能关。
- 用户要看某条规则的代码：全局规则在 `~/.openpipal/plugins/local-rules/hooks/`，在某个 Pal 里定的在 `~/.openpipal/agents/<id>/hooks/`，可以 read 出来给用户看。
