# /bugfix — Bug 修复流程

用户描述了一个 bug，按以下流程修复。

## 1. 定位

用 CLAUDE.md 中的 Quick Navigation 表格，根据 bug 症状定位到 1-2 个入口文件。
如果涉及多个子系统，用并行 sub-agent 分别研究（每个 agent 限定一个目录）。
**禁止漫游式 Read** — 3 次 Read 未找到目标就换用 Grep/Glob。

## 2. 诊断

写出以下三点，**等用户确认后再编辑代码**：
1. **Root cause**: 根因是什么
2. **Files/functions**: 涉及哪些具体文件和函数
3. **Proposed fix**: 修复方案，以及为什么它能解决根因

## 3. 修复

- 做最小化修改，不重构周围代码
- 不加多余的错误处理、注释、类型标注
- 不改不相关的文件

## 4. 验证

修复后立即执行：
```bash
npx electron-vite build   # 在仓库根目录执行
```
如果编译失败，修复类型错误后重新 build。

检查清单（逐项确认）：
- [ ] 编译通过
- [ ] 原 bug 已修复
- [ ] 未引入回归（尤其：消息顺序、宽度对齐、流式渲染、thinking 显示）

## 5. 卡住规则

同一个 bug 尝试 **2 次**仍未解决：
- 停下来
- 重新分析根因
- 向用户展示修正后的理解 + 2-3 个替代方案
- 等确认后再继续

**不要继续同一思路硬试。**
